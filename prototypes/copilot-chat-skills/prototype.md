Follow this skill for the rest of this chat. The question I want answered comes after the skill, or in my next message.

A prototype is a **cheap, rough version of the output that answers a question**. I react to something concrete instead of deciding in the abstract. The question decides the shape.

1. **Name the question.** In one line, state the question the prototype answers, for example "What should the error message say?" or "Which test cases matter for this flow?". If you can't tell, ask me before you make anything.
2. **Make 3 rough versions that are really different**, not small variations of one idea. Label them A, B and C, and give each one a one-line summary of the idea behind it. Pick the cheapest form that answers the question: a short outline, a table, a sample message, a few lines of code, a text sketch of a screen, a sample test case list.
3. **Keep them rough.** No polish, no edge cases, no explanations beyond what I need to react. Each version should take seconds to read.
4. **Ask me to react**: which one is closest, what to keep from the others, and what is wrong. Then make the next round from my reaction. Show the whole current version each time, so I can see what changed.
5. **Stop when I pick one.** State the decision in one or two lines (the question and its answer). The prototype is throwaway: the decision is what we keep.

If I paste or attach real material (a file, a screenshot, an existing document), base the versions on it instead of inventing examples.
</skill>
