Understanding first, output second: generative AI for developers and testers.

This talk was planned by letting an AI interview me, not by writing prompts.

Open2

The usual way: misunderstanding

Think of the AI as a developer who knows everything except your expectations.

  • You write a prompt. Wherever it says nothing, the AI fills the gap with a guess from its training data.
  • It guesses the most typical answer, not yours.
  • The result is confident, plausible, and not what you meant.

The AI knows everything except what you expect, so it guesses.

Grilling3

Flip it

Don't write a long prompt. Let the AI ask, and you answer, one round at a time.

It brings out

what you forgot to say.

It brings in

ideas you hadn't thought of.

Grilling means the AI interviews you until you both understand the task.

Grilling · IDE group: Cursor or Claude4

Example: a developer in the IDE

DeveloperAdd retries to the payment client. Grill me first.
AgentQ1: Which errors can be retried? Timeouts and 503s only, or every failure?
AgentQ2: Are the payment calls idempotent? If not, a retry can charge the customer twice.

In the IDE, grilling stops the agent from confidently changing the wrong thing.

Grilling · Copilot Chat group5

Example: a tester in Copilot Chat

TesterI need test cases for the new password reset flow. Before you write any, grill me.
CopilotHow long is a reset link valid? Is there a rate limit? Email only, or SMS too?forgot to say
CopilotShould a reset sign the user out of their other sessions?never thought of

The questions bring out what you forgot, and ideas you never had.

Grilling6

When to stop

  • Your answers turn into "don't care".
  • Then ask for a summary of the decisions.
  • Read it. If you would have written the same, you're done.

Stop when you and the AI would write the same spec.

Sharpen8

Shared vocabulary

"Order" means three things across our teams. Write down what each word means, once.

Cursor or Claude

Keep a GLOSSARY.md in the repo, like the one in the demo. The agent reads it.

Copilot Chat

Paste the glossary at the start of a new chat.

Agree on words once, and every later chat starts from them.

Sharpen9

Environment inspection

Your description of a problem is a guess too. Let the AI see the real material.

Cursor or Claude

Let the agent read the files and run the tests itself.

Copilot Chat

The chat can't look it up, so paste or attach the real file, error or document.

Show the AI the real thing, not your description of it.

Sharpen10

Prototype

Ask for a cheap, rough version first, and react to it.

Cursor or Claude

A throwaway HTML page or script that answers one question.

Copilot Chat

"Give me three rough versions of this bug report template."

React to something rough before you decide.

Then build11

Plan, then build

Grilling ends in a plan. Build from that plan, in a separate step.

Cursor or Claude

Save the plan to a file. Start a new session to build from it.

Copilot Chat

Copy the summary of decisions into a new chat, then ask for the output.

Decide first, build second.

Then build12

Smart zone

A long chat full of old tasks makes the AI less sharp. One task per chat.

Cursor or Claude

/clear or a new session.

Copilot Chat

The New chat button.

Start a fresh chat for each task to keep the AI at its sharpest.

Then build13

Skills

A skill is a reusable prompt that sets how the AI works on a kind of task, such as grilling.

Cursor or Claude

Install the skill. The tool loads it when the task needs it.

Copilot Chat

Paste the skill, in its <skill> tags, at the start of a new chat.

Write down how you want the AI to work once, then reuse it.
